# Known limitations

- The English DistilBERT classifier is experimental. The **currently public v0.2 model** has benign FPR 0.161 on the 116-case Deepset test, 0.286 on the 50-case authored fixture, and 0.750 on the old 30-case regression. The unpublished v0.3 candidate improved these to 0, 0.143 and 0.500 respectively, but missed one additional attack on each of the old 30-case and Deepset tests. On its frozen 120-case authored test, v0.3 had 9 false alarms among 80 benign cases. A pinned external direct-user diagnostic found 4/1,050 v0.3 false alarms but 359/1,051 labeled attacks missed; some labels are ambiguous. Neither distribution establishes deployment accuracy or passes the proposed beta evidence gate; see the [candidate evaluation](reports/v0.3-evaluation.md) and [external diagnostic](reports/v0.4-external-diagnostic.md).
- The model score is not a calibrated probability of prompt injection or attack success. Evidence spans identify inspected model windows, not exact attack tokens. A negative scan cannot prove that a malicious instruction is absent or that an LLM will resist it.
- Training data are limited, mixed-origin and mostly short English text. Multilingual text, distribution shift, long documents, novel encodings and new attack strategies need independent evaluation. Complete inspection means supported bounded views/windows were processed, not semantic completeness.
- A default installation without the derived local ONNX model reports `INCOMPLETE`; it does not classify with rules or an untrained/third-party model. `kjnlae model download` verifies the reviewed ~268 MB public v0.2 checkpoint and derives a separately hashed ONNX artifact. The original checkpoint and its private backups remain unchanged. See [runtime provenance](onnx-runtime.md).
- The six attack-lab cases have scripted proposals and synthetic local effects. They demonstrate the implemented authorization boundary, not a real LLM's attack-success rate or a production hospital/enterprise rollout.
- `GuardedExecutor`'s catalog lock/version recheck is a local synthetic adapter. A real external database or tool must enforce the equivalent check transactionally. Apps that invoke tools outside this gateway receive no protection from it.
- Known-secret, destination and field checks cannot detect arbitrary sensitive data or all disguised URLs. Hosts must limit access before generation and apply domain-specific release controls.
- The static API key and authority file support a single service identity. Multi-user authentication, tenant routing, reviewer ceremonies and distributed approval storage belong to the integrating host. Approval tokens are process-local and expire on restart.
- BIPIA and Deepset imports require pinned lawful source acquisition. AgentDojo and BIPIA full external benchmarks were not run. The Deepset license declarations differ between API and nested metadata; downstream distribution requires independent review.
- Historical Docker and Windows/macOS checks used the prior PyTorch runtime and do not verify the new ONNX path. A fresh target-host install and Windows/macOS real-weight checks are still needed. Refer to [runtime provenance](onnx-runtime.md) and [verification](verification.md) for current executed checks and unverified items.
- The v0.3 weights are unpublished and exist only in the cloud workspace. The default installer remains pinned to the public v0.2 identity until publication, immutable revision verification, and a separate application update. The code on the v0.3 development branch can use the reviewed candidate only with its exact local directory and manifest hash. The candidate's 50% benign false-positive rate on the old regression set is a serious usability limitation.
