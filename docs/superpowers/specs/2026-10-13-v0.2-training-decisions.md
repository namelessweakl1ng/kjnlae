# v0.2 CPU training decision record

Status: specification revision for review; implementation and training not begun.
This supplements [the existing specification](2026-10-13-v0.2-design.md), not a
new implementation plan. The original baseline assessment/reports remain unchanged.

## Confirmed user decisions

- Free CPU-only training in the current cloud execution environment; no paid GPU.
- Real PyTorch fine-tuning, not simulated training or merely installing a detector.
- English initially.
- Public appropriately licensed examples and original synthetic examples using
  fictional healthcare/company data. Individual sources require provenance review.
- Initial trained artifact distribution through a verified local model directory.
- Measure inference latency, memory and size first; agree deployment limits from
  results instead of assuming numeric requirements.
- Combined custom NLP plus deterministic detection by default in all consumers.
- Missing/broken model must produce explicit incomplete/error status, not a claim
  that combined scanning ran successfully.
- Specification approval, then implementation-plan approval, then implementation.
- Report CPU feasibility measurements before a full run; ask before consequential
  changes, model/environment substitution or paid resources.
- Preserve an architecture-compatible future DeBERTa GPU option without requiring
  GPU access for v0.2.

## Recommended model, still proposed

DistilBERT base uncased, pinned revision
`12040accade4e8a0f71eabdb258fecc2e7e948be`; reviewed public metadata/config list
Apache-2.0, safetensors, six layers, hidden size 768 and 512 positions. Suitable
English-first candidate with lower compute than the twelve-layer DeBERTa reference.
No training speed, compatibility, accuracy or memory claim has yet been measured.
Verify license/tokenizer/artifact hashes before any approved acquisition.

A much smaller two-layer BERT was also inspected at revision
`30b0a37ccaaa32f332884b96992754e246e48c5f`; Apache-2.0 metadata, safetensors,
two layers and hidden size 128. It is an alternative with lower capacity; switching
to it requires approval after measured limitations, not a silent fallback.

DistilBERT has no pretrained prompt-injection head. Its before-training comparison
is an explicitly labeled seeded untrained-head control. Gains over that control
alone do not demonstrate gains over an established injection classifier. A separate
Protect AI reference comparison remains a proposed optional addition, not our model.

## Proposed experiment for approval

Real full encoder/head CPU optimization on 64 approved TRAIN-only examples; seed
42, FP32, batch 2, 128 tokens, four compute threads, AdamW starting LR 2e-5.
These are probe settings, not finalized full-run hyperparameters.

Bound: 32 optimizer steps and ten minutes of worker wall time after artifact
preparation, including load/export/reload. Resource stop conditions: worker-tree
RSS above 12 GiB, total cgroup usage above 28 GiB, less than 8 GiB free workspace,
non-finite gradients/loss or deadline. Parent watchdog enforces cleanup.

Measure warm-up/steady-state speed, throughput, memory, loading/export/reload and
artifact size; prove parameter updates and real offline inference from exported
safetensors. No probe accuracy is presented as release accuracy.

Present estimated full-run duration with sequence-length/checkpoint/validation
uncertainty and obtain approval before full training. If the probe is impractical,
report completed steps and bottleneck; ask before changing model or environment.

## Required training and verification additions

Four immutable partitions: train for updates, validation for weights/early stopping,
calibration for thresholds, held-out test for final comparison. Group source/template/
paraphrase/conversation families; remove exact/near duplicates; freeze independent
held-out templates. Keep original v1 regressions out of training.

Compare rules, pre-training control, genuinely fine-tuned model and combined
pipeline; report actual counts, provenance, quality and CPU resource results.
Require real exported-weight checks in CLI/SDK/API/dashboard and RAG/hospital/
enterprise integrations. Core mocked tests are useful but not model evidence.

README must document executed Fedora setup, preparation/training/resume/export,
local model installation, combined defaults/failure handling and verification.
No weights enter Git; no paid service or public artifact upload is authorized.

## Approval boundaries

The architecture document is proposed. Its approval permits the detailed

The feasibility result then informs separately approved full-run configuration and
