# kjnlae v0.2 Model-Only Gateway Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a reusable gateway whose only prompt-injection detector is our actually fine-tuned English DistilBERT model, with complete inference, honest failure states, independent authorization, three synthetic applications, and measured evaluation.

**Architecture:** The host supplies verified identity, task, grants, resource catalog and deployment policy. Bounded preprocessing maps the original and supported derived views into windows; one verified local model classifies every window. Separate policy, execution and output gates enforce permissions even on model misses. Training, calibration and artifact promotion are isolated from runtime inference.

**Tech Stack:** Python 3.12+, FastAPI/Pydantic, PyTorch/Transformers/safetensors in optional inference and training groups, SQLite, pytest, Ruff/mypy, React/TypeScript/Vite. Four effective CPU cores, 32 GiB cgroup RAM; no GPU or paid service.

**Spec:** [approved v0.2 design](../specs/2026-10-13-v0.2-design.md) at `e2df029b322cb251382da5c6fb33ed2a54954729`; [training decisions](../specs/2026-10-13-v0.2-training-decisions.md). User approved this plan at `150dd1f9df52a475adbeb463c79404836ec87f33` and authorized native execution of all 22 tasks, including full CPU training if the bounded probe confirms feasibility.

## Global Constraints

- The sole application injection detector is **our trained** DistilBERT; no keyword/regex/rule, third-party, mock or untrained-model fallback. Remove `deterministic`, `combined` and mode selection from v0.2 surfaces.
- Parsing, Unicode normalization, bounded decoding, ACLs, exact approvals, destination checks and output DLP may use deterministic code; none may assign an injection label/severity.
- Retain 32,768-character scan and 128 KiB HTTP body caps. Proposed derived-view budgets are eight views, depth two, 16 encoded candidates, 4,096 characters each, 8,192 total decoded characters; exhaustion is incomplete/rejected, never silently truncated.
- English-first DistilBERT base uncased starts at exact revision `12040accade4e8a0f71eabdb258fecc2e7e948be`; verify license/files before acquisition. Use CPU FP32, no remote code, local-only safetensors at runtime. No weights in Git.
- TRAIN updates weights, VALIDATION selects checkpoints, CALIBRATION chooses thresholds and window aggregation, HELD_OUT_TEST measures the frozen model once. Public data needs per-source license/provenance; medical/company examples are fictional.
- Initial artifacts live in a verified local directory; no paid GPU, hosted service, public model upload or assumed cloud-session retention.
- The first training activity after plan approval is the bounded **64 TRAIN examples / 32 optimizer steps / 10-minute worker deadline** feasibility probe (including export/reload), with the spec's 12 GiB worker RSS, 28 GiB cgroup-use and 8 GiB free-disk stops. Prepare its prerequisites first. Record actual measurements and use them to choose and document the full-run configuration. The user expressly authorized proceeding to full CPU training without another approval if the probe establishes feasibility. Stop and report a genuine infeasibility, unmet critical security requirement, or choice outside the approved specification.
- An absent/corrupt/timed-out/partial model returns INCOMPLETE/error. General content requires review; sensitive content blocks. No successful scan is possible without the approved artifact. Resource authorization and output checks remain independent.
- Historical v0.1 detector metrics may be shown only as labeled archived reports; the v0.2 application and benchmark code cannot import or execute `detection/rules.py`.
- Each task follows red → green → focused regression → commit. Never relax security assertions. At milestone reviews inspect full diff, data provenance and executed output. Continue on the existing development branch unless the user explicitly requests a separate worktree; no product code or training in this planning stage. During staged migration, record expected failures of legacy full-suite tests until Task 17 updates their API contracts; each new focused suite must pass before its commit.

## Review Focus

1. A Base64/HTML/comment payload in a **late derived view/window**: Tasks 5 and 10 must prove the model receives that window or the scan is INCOMPLETE, even when earlier windows are negative.
2. A forged `principal`, tenant, analysis purpose or approval in a request/document: Tasks 1, 9, 12 and 17 must reject it as authority while allowing a verified host context.
3. A model directory containing correct-looking labels but altered weights, tokenizer or manifest: Tasks 4, 8 and 17 must fail artifact verification and never load another model.
4. An approval replay with changed destination, parameters, tenant or resource version: Task 12 must show zero executor callbacks and one-use token consumption only for the exact action.
5. A benign patient/employee request alongside an injected retrieved note and a model miss: Tasks 11 and 14–16 must keep the request's injection label separate from the ACL decision, deny the unauthorized resource/export, and complete permitted reads.

## File ownership and interface map

| Owner | Files (create/modify) | Contract used by later tasks |
|---|---|---|
| Public contracts/trust | `src/kjnlae/schemas_v2.py`, `context.py`, `schemas.py` | `ContentEnvelope`, `TrustedSecurityContext`, `InspectionRequestV2`, `InspectionResultV2`, `AuthorizationResultV2`; legacy types only for non-detection compatibility |
| Input preparation | `src/kjnlae/detection/preprocessing.py`, `detection/inspection.py` | `prepare_views(text: str) -> PreparedInput` containing mapped `InspectionView`s and coverage diagnostics; never attack findings |
| Data and training | `src/kjnlae/training/{dataset,prepare,probe,fit,report}.py`, `datasets/fixtures/v2_seed.jsonl` | immutable split manifests, `probe(config) -> ProbeReport`, `fit(config) -> TrainingReport`; TRAIN-only probe |
| Model artifacts/inference | `src/kjnlae/classifiers/{artifacts,local}.py` | `verify_artifact(path, expected_hash) -> ArtifactManifest`; `LocalClassifier.classify_views(views, source) -> ModelInference` with scored windows/status/coverage |
| Scan policy | `src/kjnlae/policies/{config,decision}.py`, `guard.py` | `Guard.inspect(request, trusted_context=None) -> InspectionResultV2`; model scores alone supply injection evidence |
| Enforcement | `src/kjnlae/guards/{actions,executor,output}.py` | tenant-aware `ActionGateway.authorize(...)`; `GuardedExecutor.execute(...)` calls only host-registered adapter; `OutputGuard.release(...)` protects outgoing content |
| Integration | `src/kjnlae/integrations/rag.py`, `examples/{rag,hospital,enterprise}.py` | `RagGateway.retrieve(...) -> RetrievalResult`; synthetic apps call real scanner and host-owned guards |
| Delivery | `src/kjnlae/api/{app,config}.py`, `storage/sqlite.py`, `cli.py`, `frontend/src/*`, docs/scripts/CI | `/v2/*`, model-only CLI/dashboard, privacy-aware history, verification reports |

Types/names above are frozen plan contracts. Every consumer passes the same bounded source/content representation to the model; `TrustedSecurityContext` is created by host code or a server resolver, never trusted from HTTP JSON. A scan result never grants a tool. `MODEL_MISSING`, `ARTIFACT_INVALID`, `MODEL_TIMEOUT`, `MODEL_ERROR` and `COVERAGE_EXCEEDED` are explicit failure reason codes. The source-kind prefix is descriptive model input and never an identity grant.
