## Diagnosis and data separation

The original 660-row TRAIN split had 54 injection and only 5 benign examples with source `retrieved_document`, while 347 benign rows had source `user`. The model assigned high attack scores to ordinary retrieved text, quoted attacks and code. This is evidence of source-label confounding and insufficient hard benign examples; it does not prove those are the only causes.

Before changing TRAIN, commit `1a307c5` froze a new, original, fictional [50-case evaluation set](../../datasets/fixtures/v0.2-independent-eval.json): 35 benign and 15 active attacks across user, retrieved document, webpage, email, tool response and attachment sources. Its SHA-256 is `a70629b432dda5ad0a6a91ba87a35bffd594752af7d7ab1d39f2f29ee34438bc`. Exact normalized text overlap against prior TRAIN and the 30-case regression set was zero. It was never used for training, checkpoint selection or calibration. It is a small authored fixture, not an external benchmark or statistically representative sample.

TRAIN then added 64 new fictional benign examples (SHA-256 `2f846ed89ab8b9d9111e27c927289c6e91734de9880c6487dc1cfe908b2e91c1`) covering quotation, documentation, code, RAG, enterprise and healthcare contexts, plus 200 deterministic source-balanced variants of **public TRAIN benign** rows. The variants retain their original text, label, family and public provenance; they change only the source field, are TRAIN-only, and are regenerated with seed 43. Their local SHA-256 is `277998b7e770a29c5e49e805e0a8cb103717b73e50cbef0a4a9d23c36ed57346`. The new TRAIN split has 924 rows (639 benign, 285 attack), SHA-256 `a20fe7bd4e2a1d7fbd5da81d68a81ce37b52e724ff7a272aa7c4b7145bb911af`. The separate 12-row VALIDATION, 12-row CALIBRATION and 116-row Deepset HELD_OUT_TEST files are byte-identical to the prior run. No regression or independent-evaluation case entered TRAIN.

An initial 300-second CLI run ended `INCOMPLETE` at 272.47 seconds because its checkpoint guard stopped before the larger epoch could finish. It promoted no model. A separate 600-second bounded run completed 924 optimizer steps in two epochs, in 351.13 seconds wall time, with 1,889,947,648-byte peak worker RSS and 25,292,435,456-byte peak cgroup use. VALIDATION F1 at threshold 0.5 selected epoch 1 (0.857 on 12 rows); the deployed checkpoint therefore represents **462 trained steps**, while 924 is the run's total. The trained weights SHA-256 is `0367a9d7b42f288a25d0d9f3c86d4b10b55b919652d504db535da28313b8f89a`, distinct from initial weights `82c89acc833e07cef4238a36f4150f267083c0015c318060514ea03777eaf9a4`. CALIBRATION selected threshold `0.025134501978754997` on only 12 rows. That low threshold is unstable and may contribute to false positives; it was chosen without using either evaluation fixture or held-out test. The reviewed release copy preserves the same weights with an explicit `EXPERIMENTAL` status and corrected checkpoint-step count; it is **not** a quality-approved production model.

All 50 new cases and all 30 regression cases were completely scanned in each run. On the candidate's 50-case set, all five benign RAG cases passed, but four of five benign code cases and three of five quotations still failed. Mean end-to-end scan latency across those 50 cases, including the first worker startup, was 82.82 ms versus 77.34 ms for the original artifact. Candidate CPU forward-pass mean on the Deepset test was 0.0339 seconds per case; worker startup and policy overhead are excluded. These tiny sets do not support claims of calibrated probabilities, generalization or production readiness. The candidate improves one independent distribution and worsens the Deepset split; it has **not** solved false positives.

The six synthetic sandbox cases now use host-owned analysis intent for the educational quotation, producing `WARN` while allowing only an independently authorized public read. Both benign tasks complete (2/2); all four unauthorized proposals are denied (4/4), including a detector miss. These are scripted local effects, not live-LLM attack success measurements. Missing or corrupt model files still produce explicit incomplete/error outcomes and cannot clear content.

The raw score, fit and benchmark JSON reports are committed beside this report. Exact rerun commands and source acquisition are in [model training](../model-training.md). Further model changes need another independent evaluation set; repeatedly tuning on these 50 or 30 fixtures would contaminate the comparison.
