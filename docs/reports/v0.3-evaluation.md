# v0.3 DistilBERT candidate: measured evaluation, 18 October 2026

This is a **local, unpublished release candidate**, not a production-ready
security claim. The public installer still downloads v0.2. The candidate
meets the [predeclared frozen-set gate](v0.3-experiment-protocol.md) after a
documented development-only correction to its threshold tie-break. It does
not eliminate false positives, and authorization remains independent of the
detector. The complete [model card](../model-card-v0.3-candidate.md) and
machine-readable reports linked below provide provenance and exact counts.

## Diagnosis and experimental change

The public v0.2 model flagged 9/12 benign cases in the original regression
set, 10/35 in the earlier independent fixture, and 9/56 in Deepset TEST.
Earlier training had few benign lower-trust documents relative to direct-user
data. Its threshold `0.025134501978754997` was chosen on only 12 calibration
examples. On the new frozen set, raising **the old model's threshold alone**
using the separate development calibration split reduced benign false alarms
from 34/80 to 16/80 while finding all 40 attacks. Thus both training and
threshold contributed to the public model's false-positive problem; their
relative effects cannot be inferred from one small test.

The data audit also found that the context-free Deepset positive class
includes ordinary direct-user roleplay or new-topic requests. Such requests
are not necessarily prompt injections under kjnlae's trust-boundary threat
model. This is a label-compatibility concern, not proof that every Deepset
positive is mislabeled. The v0.3 candidate still uses the pinned public
TRAIN rows and inherits v0.2 weights, so the issue remains a limitation.

Before training or scoring, commit `c35e7c2` froze 120 new fictional final
cases (80 benign, 40 active attacks) and quantitative release targets. New
source-balanced authored data contributed 160 TRAIN, 40 VALIDATION, and 80
CALIBRATION rows. The complete TRAIN mix was 884 rows (539 benign, 345
attack). All final and historical tests stayed out of optimization,
checkpoint selection, and calibration. Validation/calibration source variants
reduce their effective independent family counts to 20/40. A bounded
32-step CPU probe completed before full training. The full continuation run
from verified v0.2 weights completed 884 steps in 433.77 seconds, with
1,867,456,512-byte peak worker RSS. Epoch 2 was selected by validation F1;
the source checkpoint SHA-256 is
`6c0896d72a1ef5bc5f49bd815412f8f66750055696ab716c6956ef872712c321`.

The original selection rule preferred the lowest threshold satisfying
calibration FPR ≤10% and recall ≥90%. Its first result, `0.0003606959`,
unnecessarily retained false alarms when `0.5` gave the same recall with
fewer. Before opening final data, the rule was amended to maximize recall,
then minimize FPR, then prefer the value closest to `0.5`. Both initial and
amended selection reports are preserved. The sealed candidate threshold was
**0.5**. On 80 calibration rows it had TP 38, TN 40, FP 0, FN 2; on 40
validation rows it had TP 20, TN 20, FP 0, FN 0. Perfect validation on 20
authored families is not a deployment accuracy estimate.

The new frozen-set benign FPR fell 73.5% relative to the public v0.2
operating point and 43.75% relative to recalibrated v0.2. The candidate
found all 40 labeled attacks. Its descriptive 95% Wilson FPR interval is
6.0–20.0%; the recall interval is 91.2–100%. The examples were authored by
the project and grouped by topic, so these intervals understate uncertainty
about real traffic. The old 30-case regression remains poor at **50% benign
FPR**, with an additional missed attack compared with v0.2. Deepset TEST
also has one additional missed attack. These are real limitations, not
discarded outliers.

## Conversion, runtime, and security boundaries

The separately packaged candidate source manifest SHA-256 is
`071f6166177efd4af978e46d2f44fae13fe1a4be8c2030c916c3b924ecfe4d61`.
The verified ONNX model SHA-256 is
`aee933ab961a49d6c57ce0260220034b3e6e23177fc00602aa4e83578eb2106f`
and its manifest SHA-256 is
`537899c45553fc6583587684c5685d57c159c1b9f387590b182e1ce0f9a9ea4c`.
The weight-free template is unchanged because tensor shapes are unchanged;
the **filled ONNX graph and identity are new**. PyTorch and ONNX scored all
120 cases across 124 token windows, including final-window coverage, with
matching view names and source offsets, zero decision flips, and maximum
per-window absolute score difference `5.781650543212891e-06`.

Actual candidate `Guard` scans completed all 120 cases. Warm mean scan time
was 24.31 ms versus 16.85 ms for v0.2, or about 1.44 times slower on this
machine. Cold-start-inclusive means were 39.55 ms and 30.10 ms. A separate
actual-weight test checked a long attack near the end of input and verified
complete window/offset parity. The app still returns `INCOMPLETE` for
missing, corrupt, timed-out, or incompletely inspected models; no regex or
untrained fallback was introduced. `ActionGateway`, `GuardedExecutor`,
tenant/resource grants, human approvals, destination restrictions, and
`OutputGuard` are independent of model scores. The scripted sandbox is
not a live-LLM attack-success benchmark.

Local release verification with the candidate configured passed **129 Python
tests, 2 skipped**, Ruff, mypy, **7 frontend tests**, frontend build, wheel
build, real-model `doctor`, and the fixture benchmark. Hosted CI has not yet
run on this branch. The runtime-only Python dependency audit found no known
vulnerabilities, and the production frontend audit found none. The broader
maintainer venv audit reported 32 advisory entries in `transformers 4.51.3`
and `setuptools 78.1.0`; they are optional training/build dependencies and
must be reviewed before another training environment or source release is
considered hardened. No untrusted remote code or pickle model weights were
loaded in this run. Full AgentDojo/BIPIA benchmarks, production deployment,
and real-weight Windows/macOS/ARM tests remain unverified.
