# v0.3 development data and CPU probe

The 120-case [frozen final set](v0.3-experiment-protocol.md) was committed at
`c35e7c2` before preparing candidate data or scoring models. The development
partitions contain 884 TRAIN (539 benign, 345 attack), 40 VALIDATION (20/20),
and 80 CALIBRATION (40/40) rows. No final-test row appears in these partitions.
The prepared manifest is stored outside Git in
`/workspace/kjnlae-v03-work/data/prepared/manifest.json`; its split hashes are:

| Partition | SHA-256 |
|---|---|
| TRAIN | `65eacad9bcd94ab7b764279ed632e1b9d6fd3e666769b5c01be4b4099753e430` |
| VALIDATION | `d139045b859040d42a891a0d74a058c3bd3ec80ba68ded9c8616caf60c6b7ce6` |
| CALIBRATION | `4b10f6ea677557f46785faa20fe23ed0d77e58f94b969a5e44d208e66ecdd454` |

The training mix uses the pinned Deepset TRAIN parquet (546 rows, source
SHA-256 `2e10bc7ab30f542c97e4e83e2a5683000b5057d25ec10908784c631d44124c04`),
50 Microsoft-authored BIPIA TRAIN attacks (source SHA-256
`63f95d3e67eac4178cdabdbdaf192cd05f2b6ed0702b578f1d30d556e5155670`),
64 original v2 TRAIN cases, 64 earlier authored hard benign cases, and 160
new authored TRAIN rows. The new 40 validation and 80 calibration rows are
authored for this experiment. Public source revisions and attribution terms
remain documented in [model data](../model-data.md); BIPIA MIT/NOTICE applies,
and the Deepset Apache-2.0 versus CC BY 4.0 metadata discrepancy requires
observing both sets of attribution obligations. No public raw data is committed.

The new authored rows are generated reproducibly by
`src/kjnlae/training/v03_data.py`. A second lower-trust source presentation
of each authored text remains in its **same family and same partition**. This
balances labels across source types but does not double the number of
independent semantic cases. VALIDATION has 20 unique authored families and
CALIBRATION has 40. Their small effective size and synthetic wording still
limit threshold reliability. Each development split contains both classes
across retrieved documents, webpages, emails, attachments, and tool results.
TRAIN remains dominated by Deepset direct-user examples, though the added
source presentations reduce the source-label skew. The preparation code
rejects duplicate IDs, cross-split families and normalized or near-duplicate
cross-split text. A separate >=0.85 string-similarity check found no collision
with the frozen final set. Lexical checks cannot establish semantic novelty.

The bounded probe loaded the **verified published v0.2 checkpoint** and ran
32 real CPU optimizer steps (batch 2, 128 tokens, seed 42, four threads). It
completed in 28.92 seconds parent wall time; worker load took 8.10 seconds.
Median steady-step time was approximately 0.44 seconds. Peak worker RSS was
1,751,097,344 bytes and peak cgroup usage was 13,563,908,096 bytes. The
before/after parameter hashes differed, and safetensors export and reload
succeeded. Probe output is experimental only and is **not** a candidate
checkpoint. With 884 TRAIN examples, two epochs imply 884 optimizer steps;
approximately 390 seconds of steady optimization plus loading, validation,
and checkpointing fit within the existing 600-second training deadline on
this machine. This is a measured feasibility projection, not a guarantee.

Regenerate the partitions from the pinned public files with
`python scripts/prepare_v03.py --deepset-train PATH --bipia-train PATH --output DIR`.
The script verifies source hashes before import and leaves the frozen final
set out of development data. Full CPU training uses the repository's existing
`train fit` command with the reviewed v0.2 checkpoint as initialization,
`--epochs 2 --deadline 600` and default 2e-5 learning rate. Keep all new
weights outside Git and never overwrite the reviewed v0.2 directory.
