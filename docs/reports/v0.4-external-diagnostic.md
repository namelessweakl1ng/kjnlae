# Pinned S-Labs direct-user diagnostic: v0.2 versus v0.3

**Measured 18 October 2026.** This is an external, unreviewed-label diagnostic and is **not** the cross-source final evaluation or a production-readiness claim. The immutable source revision, MIT declaration, exact CSV hash, split limitations and reproduction command were [recorded before scoring](v0.4-experiment-protocol.md). Neither model nor its reviewed threshold was changed after opening this split.

The original `data/test.csv` has 2,101 rows: 1,050 labeled benign and 1,051 labeled injection. The adapter maps all to `source=user`. All rows were completely inspected by real local ONNX inference via `Guard.scan`; no model fallback or mock inference was used. The v0.3 manifest was SHA-256 `537899c45553fc6583587684c5685d57c159c1b9f387590b182e1ce0f9a9ea4c` at threshold 0.5. The public v0.2 ONNX manifest was `6b69bd6a790119d4c53fe2df02447114eebcdadddec18d788bf1cf6825ecfa1c` at threshold 0.025134501978754997.

| Measured property | v0.2 | v0.3 candidate |
|---|---:|---:|
| TP / TN / FP / FN | 869 / 960 / 90 / 182 | 692 / 1046 / 4 / 359 |
| Precision | 90.62% | 99.43% |
| Recall | 82.68% | **65.84%** |
| F1 | 86.47% | 79.22% |
| Benign false-positive rate | 8.57% | 0.38% |
| False-negative rate | 17.32% | **34.16%** |
| 95% Wilson recall interval | 80.28–84.85% | 62.92–68.65% |
| Warm/cold mixed p95 scan latency | 23.47 ms | 16.62 ms |
| Complete inspections | 2,101 / 2,101 | 2,101 / 2,101 |

The experiment ran locally on an Intel Xeon Platinum 8573C with a 4-vCPU cgroup quota and 32 GiB memory limit. The first scan includes worker startup (maximum observed latency 1,472 ms for v0.2 and 1,373 ms for v0.3); the table's p95 reflects this specific direct-user prompt distribution. Runtime totals were 27.887 s and 24.531 s respectively. Memory was not measured in this run.

This distribution exposes a major trade-off: v0.3 sharply reduces labeled benign false alarms but misses 359 of 1,051 labeled attacks, including some explicit requests to reveal instructions. Manual review of a small error sample also found ambiguous positive labels such as ordinary questions about configuration or guidelines. Those labels may overstate true misses, but no row was relabeled or excluded to improve the score. The benchmark is mostly short synthetic direct-user prompts, gives no evidence for retrieved documents or tool responses, and has an unrealistic 50% attack prevalence. Its case-level Wilson intervals do not account for possible correlated families. The original 120-case authored v0.3 fixture had 9/80 benign false positives (11.25%) and 40/40 attack detections; the two distributions disagree substantially.

The candidate does **not** satisfy the proposed limited-beta evidence standard: the authored fixture exceeds its 5% benign false-positive budget, while this external diagnostic's measured recall is far below its 95% target. These sets are diagnostic rather than the required new reviewed final set, so they cannot establish a formal production pass either. The next decision is label/source-distribution review and a new frozen, multi-source, family-disjoint final set before any threshold tuning or retraining. No v0.3 model publication, installer promotion or production claim follows from this result.
