## Problem and resulting behavior

The public v0.2 DistilBERT model overflags benign quotations, code, and normal workflows, in part because its threshold was selected on only 12 calibration rows. This PR prepares a genuinely fine-tuned v0.3 DistilBERT release candidate and adds an explicitly pinned local ONNX identity. The default public `model download` remains pinned to v0.2 until the new weights are approved, published at an immutable revision, downloaded afresh, and verified. No model weights or public dataset rows are committed here.

## Data, training, and model selection

- Froze an original 120-case final fixture (80 benign, 40 active attacks) and quantitative gates before training in `c35e7c2`. Existing 30-case, 50-case, and Deepset TEST sets were excluded from training and calibration.
- Prepared 884 TRAIN rows (539 benign/345 attack), 40 VALIDATION, and 80 CALIBRATION from pinned public TRAIN sources and original fictional examples. Source variants reduce the effective validation/calibration family counts to 20/40. Dataset provenance, license discrepancies, split hashes, and labeling concerns are documented.
- Completed a real 32-step CPU probe (28.92 s, 1.75 GiB peak worker RSS), then continued fine-tuning verified v0.2 weights for 2 epochs/884 optimizer steps (433.77 s, 1.87 GiB peak worker RSS). Epoch 2 was selected on validation. Calibration selected threshold 0.5; the initial tie-break and development-only correction are preserved.
- Packaged separate safetensors and ONNX artifacts, verified their file hashes, and compared PyTorch/ONNX on all 120 final cases and 124 windows: zero decision flips, maximum score delta 5.78e-6, matching mapped views/offsets.

## Measured results (not deployment accuracy claims)

| Frozen 120-case final set | TP | TN | FP | FN | Benign FPR |
|---|---:|---:|---:|---:|---:|
| Public v0.2 threshold | 40 | 46 | 34 | 0 | 42.5% |
| v0.2 recalibrated on development data | 40 | 64 | 16 | 0 | 20.0% |
| v0.3 candidate | 40 | 71 | 9 | 0 | 11.25% |

The candidate passed the predeclared final gate on this authored fixture. It still flagged **6/12 benign** on the older 30-case regression and missed **2/18 attacks**, one more than v0.2. On Deepset TEST 116 it produced TP 57, TN 56, FP 0, FN 3, also one more miss. On the old 50-case fixture it reduced false alarms from 10/35 to 5/35. These sets are small, selected, and partly grouped; model scores are not calibrated probabilities. Mean warm full-Guard scan latency rose from 16.85 to 24.31 ms on this CPU environment.

## Security and verification

The model remains the sole prompt-injection classifier. Incomplete/missing/corrupt inference remains explicit; independent tool authorization, tenant/resource grants, approvals, and output-release checks are unchanged. The candidate requires both exact local `KJNLAE_MODEL_DIR` and `KJNLAE_MODEL_HASH`, and its derived ONNX identity is separately pinned. Long-tail real-weight coverage and parity tests were added.

Local `KJNLAE_VERIFY_RELEASE=1 bash scripts/verify_all.sh` with candidate artifacts: **129 Python tests passed, 2 skipped**, Ruff and mypy passed, **7 frontend tests passed**, frontend and wheel builds passed, real-model `doctor` and fixture benchmark passed. `npm audit --omit=dev` and runtime-only `pip-audit` found no known vulnerabilities. The broader maintainer environment audit reported 32 advisories in optional training/build packages (`transformers 4.51.3`, `setuptools 78.1.0`); those need review before a hardened training/source workflow is claimed. Hosted CI on this branch, fresh Fedora installation, real-weight Windows/macOS/ARM inference, full AgentDojo/BIPIA evaluation, and production deployment are unverified.
