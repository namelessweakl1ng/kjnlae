## Windows failure and related text I/O

The existing hosted [quality run 150](https://github.com/namelessweakl1ng/kjnlae/actions/runs/39117858268) failed its Windows `pytest` step. The Actions API returns 403 from this cloud environment, but the public run page exposes its failure status. Before editing, running `tests/training/test_v03_data.py` with `PYTHONUTF8=0 PYTHONCOERCECLOCALE=0 LC_ALL=C` reproduced the frozen fixture's `UnicodeDecodeError` at the implicit `Path.read_text()` call. The fixture includes U+2060, which cannot be decoded as cp1252 or ASCII. A separate simulated Windows newline test showed that implicit `write_text` line ending translation could change generated JSONL bytes and their reproducibility hashes.

Project-owned Python text reads/writes in `src/kjnlae/`, `scripts/` and `tests/` now specify UTF-8; writes also specify LF newlines. An AST audit found **zero** remaining `Path.read_text/write_text` calls in those directories without these explicit options. Binary file operations were left binary. The code did not change model weights, thresholds, authorization, or installer defaults.
